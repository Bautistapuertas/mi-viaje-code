Modulo 1 Fundamentos Web, Git, Scrum y TypeScript
Arquitectura Cliente-Servidor y Web
  • Cliente-Servidor: El cliente hace peticiones HTTP y el servidor responde.
  • SPA: Carga una sola vez y actualiza via JS sin recargar la pagina.
  • HTML/CSS/JS: Estructura, estilos e interactividad respectivamente.
Git
  • init / clone: Crea repo local / descarga remoto.
  • add / commit: Mueve a staging / guarda en historial.
  • push / pull: Envia al remoto / descarga y fusiona.
  • branch: Crea rama aislada.
JS y TypeScript
  • let/const: Scope de bloque. const no reasigna.
  • Promesas y async/await: Manejo de asincronismo sin bloquear el navegador.
  • TS: Tipado estatico. Detecta errores en compilacion.
  • any vs unknown: any desactiva verificacion, unknown obliga a verificar.
Scrum
  • Product Owner: Prioriza el Backlog. Representa al cliente.
  • Scrum Master: Facilita y quita impedimentos.
  • Daily: Max 15 min, solo developers para sincronizar.
  • Review / Retrospective: Muestra producto / mejora el proceso.

Modulo 2 Frontend con React (C08 a C12)
React y Virtual DOM
  • Componentes: Bloques reutilizables (funciones que retornan JSX).
  • Virtual DOM: Copia en memoria para calcular cambios minimos antes de tocar el DOM real.
Hooks: useState y useEffect
  • useState: Variable de estado. NUNCA mutar arrays con push(), siempre crear uno nuevo.
  • useEffect []: Corre solo al montar.
  • useEffect [var]: Corre al montar y cuando 'var' cambia.
Props y Context
  • Props: Datos de lectura que pasan de padre a hijo.
  • Prop Drilling: Pasar props por muchos niveles innecesarios.
  • useContext: Evita el drilling accediendo a datos globales directamente.
Routing y Zod
  • react-router: Link reemplaza a, evita recargar la pagina.
  • Zod: Esquemas de validacion estrictos para formularios controlados.

Modulo 3 Backend, Seguridad y Testing
Docker y Prisma
  • Docker: Contenedores aislados. Garantizan consistencia ("en mi maquina funciona").
  • Prisma: ORM. Mapea BD a objetos. `migrate dev` aplica cambios.
APIs REST y Express
  • Stateless: Cada peticion tiene toda la info, el server no guarda sesion.
  • Metodos: POST (Crear, 201), PUT (Reemplazar), GET (Leer), DELETE.
  • Middlewares: Si no responden, DEBEN llamar a `next()` para continuar.
AuthN vs AuthZ
  • AuthN (Autenticacion): Quien sos. Falla = 401.
  • AuthZ (Autorizacion): Que podes hacer. Falla = 403.
  • Bcrypt: Hasheo lento e irreversible de contrasenas.
  • JWT: Token stateless firmado. Header + Payload + Signature. No guardar datos sensibles en el Payload.
Testing
  • Unitario vs Integracion: Aislado vs multiples modulos interactuando.
  • Mocks: Reemplazos falsos para aislar la prueba (ej: simular Prisma).
  • RTL: Prueba la UI como la veria el usuario, no el codigo interno.
