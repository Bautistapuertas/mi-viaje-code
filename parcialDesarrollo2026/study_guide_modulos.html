Modulo 1 Fundamentos Web, Git, Scrum y TypeScript
Arquitectura Cliente-Servidor y la Web
  • Cliente-Servidor: El cliente (el navegador) hace peticiones HTTP y el servidor las responde a traves de una red.
  • HTTP: Protocolo de comunicacion entre cliente y servidor mediante peticiones y respuestas.
  • SPA (Single Page Application): Carga una sola vez y actualiza el contenido dinamicamente sin recargar la pagina entera. La ventaja principal es una navegacion mas rapida y sin interrupciones.
  • AJAX: Tecnica para hacer peticiones al servidor en segundo plano y actualizar partes de la UI sin recargar todo.
  • HTML: Estructura el contenido de una pagina web.
  • CSS: Estiliza el HTML (colores, fuentes, layouts).
  • JavaScript: El unico lenguaje que el navegador ejecuta. Se incluye con la etiqueta script.
  • Servidor web: Almacena y sirve contenido a los clientes cuando estos lo solicitan.
Git — Control de Versiones
  • git init: Crea un repositorio Git nuevo en la carpeta actual (local, no en GitHub).
  • git clone [url]: Descarga una copia completa de un repositorio remoto con todo su historial.
  • git add: Mueve archivos al area de staging, preparandolos para el commit.
  • git commit -m: Guarda una foto permanente del staging en el historial local.
  • git push: Sube los commits locales al servidor remoto (GitHub).
  • git pull: Descarga los cambios del remoto y los fusiona en la rama local.
  • git branch: Crea una rama para trabajar aislado sin romper el codigo principal.
  • git log: Muestra el historial completo de commits.
  • git status: Muestra que archivos estan modificados pero no en staging.
JavaScript Moderno y Asincronismo
  • let / const: Reemplazan a var. const no se puede reasignar. Scope de bloque.
  • Arrow functions: Sintaxis corta: const suma = (a, b) => a + b
  • Desestructuracion: const { nombre } = persona extrae propiedades directamente.
  • Spread (...): Desparrama un array u objeto. Clave para no mutar el estado en React.
  • Promesas (Promise): Objeto que representa el resultado futuro de una operacion asincrona. Estados: pending, fulfilled o rejected.
  • async / await: Sintaxis mas legible para Promesas. await pausa la funcion hasta que la Promesa resuelva sin bloquear el navegador.
  • fetch(): Funcion nativa que hace peticiones HTTP. Devuelve una Promesa.
TypeScript
  • Que es: Superconjunto de JavaScript con tipado estatico. Se transpila a JS puro. Detecta errores en tiempo de compilacion, no en ejecucion.
  • Extensiones: .ts (TypeScript puro) y .tsx (TypeScript con JSX para React).
  • Primitivos: string, number, boolean. Tambien void para funciones que no retornan.
  • any: Desactiva toda verificacion de tipos. Es un escape, no un primitivo.
  • unknown: Version segura de any. Obliga a verificar el tipo antes de usar el valor.
  • Interfaces / Types: Definen la forma de un objeto. Ej: interface Usuario con id y nombre.
Metodologia Scrum
  • Sprint: Iteracion de 1 a 4 semanas. Al final se produce un incremento del producto.
  • Product Owner: Representa al cliente. Unico responsable de priorizar el Product Backlog.
  • Scrum Master: Facilita el proceso y elimina obstaculos. No es el jefe del equipo.
  • Developers: Hacen el trabajo. Se auto-organizan.
  • Sprint Planning: Al inicio del Sprint. El equipo elige que items pasan al Sprint Backlog.
  • Daily Scrum: Reunion de max 15 min diaria, solo Developers. Objetivo: sincronizarse y detectar bloqueos.
  • Sprint Review: Al final. Se muestra el trabajo terminado al cliente.
  • Sprint Retrospective: Al final. El equipo reflexiona sobre como mejorar su proceso.

Modulo 2 Frontend con React (C08 a C12)
Componentes, JSX y Virtual DOM
  • Componentes: Funciones de JavaScript que retornan JSX. Son los bloques de construccion de la UI.
  • JSX: Sintaxis que mezcla HTML dentro de JavaScript. El compilador lo transforma a llamadas JS puras.
  • Props: Argumentos que el componente padre pasa al hijo para configurar su comportamiento. Son de solo lectura dentro del hijo.
  • Virtual DOM: Copia ligera del DOM real en memoria. React la usa para hacer Diffing y aplicar solo los cambios minimos al DOM real.
useState — Estado Local
  • Declara una variable de estado. Cuando se actualiza con su setter, React re-renderiza el componente.
  • Por que no usar let: Una variable let comun no dispara el re-render aunque cambie.
  • Regla para arrays: Nunca usar .push() en el array original. React compara referencias, si mutamos el original cree que nada cambio. Siempre crear uno nuevo: [...viejo, nuevoElem]
useEffect — Efectos Secundarios
  • Con [] (array vacio): Se ejecuta SOLO al montar el componente. Ideal para llamadas API iniciales.
  • Con [variable]: Se ejecuta al montar Y cada vez que esa variable cambia.
  • Sin array: Se ejecuta despues de CADA render. Cuidado con loops infinitos.
  • Sirve para efectos secundarios: fetches, timers, suscripciones, manipulacion del titulo de la pagina.
useContext — Estado Global y Prop Drilling
  • Prop Drilling: Pasar props por multiples niveles de componentes que no los necesitan directamente. Es codigo dificil de mantener.
  • useContext: Permite que cualquier componente del arbol acceda a datos globales (usuario logueado, tema) directamente, sin pasar por intermediarios.
Routing y Formularios
  • react-router-dom: Navegacion entre "paginas" sin recargar. Usa BrowserRouter, Routes, Route y Link (reemplaza la etiqueta a).
  • Formularios controlados: Los inputs estan atados al estado con value y onChange. React tiene control total.
  • Zod: Libreria para validar datos con esquemas estrictos (email, longitud minima, etc.).

Modulo 3 Backend, Seguridad y Testing (C13 a C21)
Docker
  • Que es: Plataforma para empaquetar aplicaciones en contenedores aislados. Mas liviano que una VM porque comparte el kernel del SO.
  • Beneficio clave: La app corre identica en cualquier entorno. Elimina el "en mi maquina funciona".
  • docker-compose: Define y corre multiples contenedores a la vez (app Node + Postgres, por ejemplo).
APIs REST — Verbos y Codigos HTTP
  • Stateless: Cada peticion debe contener toda la informacion necesaria. El servidor no guarda contexto entre peticiones.
  • GET: Leer datos. Sin efectos secundarios.
  • POST: Crear recurso. Respuesta: 201 Created.
  • PUT: Reemplazar recurso completo.
  • PATCH: Modificar parcialmente un recurso.
  • DELETE: Eliminar recurso.
  • 200: Exito. 201: Creado. 400: Datos invalidos. 401: Sin sesion (AuthN). 403: Sin permiso (AuthZ). 404: No existe. 500: Error servidor.
Express y Middlewares
  • Express.js: Framework minimalista sobre Node.js para construir APIs.
  • Middlewares: Funciones que interceptan request-response. Tienen req, res y next.
  • Si el middleware responde (res.json etc.) el ciclo termina. NO llamar next().
  • Si NO responde (solo valida), DEBE llamar next() o la peticion queda colgada.
  • req.body: Datos del cuerpo. req.params: Variables de la URL. req.query: Parametros despues del ?
Prisma ORM y Base de Datos
  • ORM: Puente entre objetos de codigo y la base de datos relacional. Evita escribir SQL manual y previene inyeccion SQL.
  • schema.prisma: Define modelos (tablas), campos y relaciones.
  • npx prisma migrate dev: Lee cambios en el schema, genera SQL, lo ejecuta en la BD y regenera el Prisma Client.
  • Seeders: Script para poblar la BD con datos iniciales.
Seguridad — AuthN, AuthZ, Bcrypt y JWT
La diferencia entre 401 y 403 es uno de los temas mas repetidos en los parciales.
  • Autenticacion (AuthN) — 401: Verifica la identidad. Si no hay token o es invalido: 401 Unauthorized.
  • Autorizacion (AuthZ) — 403: Verifica los permisos del rol. Ocurre DESPUES de autenticar. Sin permiso: 403 Forbidden.
  • Bcrypt: Hashea contrasenas de forma irreversible. Nunca guardar en texto plano. Es intencionalmente lento para resistir ataques de fuerza bruta.
  • JWT: Token con Header + Payload + Signature. Firmado pero NO encriptado. Nunca guardar datos sensibles en el Payload.
  • Ventaja JWT: Stateless. El servidor no guarda sesiones en la BD.
  • OAuth: Protocolo para delegar autorizacion entre apps (ej: Login con Google).
  • MFA: Autenticacion multi-factor. Los tres factores: algo que sabes, algo que tenes, algo que eres. El email no es un factor MFA.
  • CORS: El navegador bloquea peticiones entre origenes distintos. El backend configura cors para permitirlas.
Testing (C20 y C21)
Las diapositivas C20 y C21 no estan en la carpeta todavia. Contenido basado en el temario estandar de la materia.
  • Test Unitario: Prueba la unidad mas pequena de forma aislada. Sin red ni BD real.
  • Test de Integracion: Prueba como interactuan multiples modulos entre si.
  • Test E2E: Simula el flujo completo del usuario.
  • describe() / it() / expect(): Agrupar tests, definir un caso, hacer la asercion.
  • Mocks: Reemplazos falsos de dependencias para aislar la unidad bajo prueba.
  • React Testing Library: Probar componentes desde la perspectiva del usuario, no de la implementacion interna.
